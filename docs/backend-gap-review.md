# 后端一致性检查与后续缺口

本文档基于当前后端源码与根目录 `/docs` 对照整理，目标是回答两件事：

- 现有后端代码和文档是否一致
- 从功能角度看，后端接下来还缺什么

## 1. 本轮已修正的文档漂移

### 1.1 管理员初始化

当前代码行为：

- `init_database.py` 只会在显式提供 `ADMIN_AUTH_SUBJECT` 时预创建管理员
- 如果没有提供，脚本会跳过预创建，并推荐让 Casdoor 管理员首次登录时按 claim 自动创建本地管理员

因此文档上不应该再写成“初始化脚本会直接创建绑定 SSO subject 的管理员账号”。

### 1.2 SSO 角色同步

当前代码行为：

- 新用户首次登录时，Casdoor claim 会决定本地初始角色
- 之后每次 SSO 登录，后端仍会继续同步 `admin/writer`
- 但 `banned` 保持本站本地控制，不会被 Casdoor 自动解除

因此文档上也不应再写成“claim 只作用于首次创建用户”。

### 1.3 故事接口列表

当前代码已经稳定提供：

- `GET /api/v1/story/node/{node_id}/lineage`
- `GET /api/v1/story/node?parent_id=...`
- `GET /api/v1/story/user/{user_id}/nodes`

这些接口都已经进入前端主链路，应明确记录在 API 文档里。

### 1.4 历史迁移文档

`casdoor-sso-migration-plan.md` 现在更适合作为“迁移背景与设计记录”，而不是当前实现状态文档。

## 2. 当前后端功能闭环情况

就主链路而言，后端已经具备这些能力：

1. Casdoor 登录后换取本站本地 token
2. 新用户首次登录时按 claim 初始化角色，并在后续登录时同步普通/管理员角色
3. 故事活动、故事树、节点详情、节点提交、节点审核
4. 评论、点赞、通知
5. 管理员仪表盘、待审核列表、用户管理

这意味着核心产品链路已经具备：

- 登录
- 看树
- 看节点
- 投稿
- 待审核
- 审核通过/驳回

## 3. 还缺什么

### 3.1 自动化测试已经起步，但还没覆盖全部修改型接口

当前后端已经有：

- mock 业务单元测试
- 基于 SQLite 的 HTTP 集成测试

但还值得继续补的测试包括：

- `/story/node/{id}` 更新
- `/story/node/{id}` 归档/删除
- `/interaction/comment/{id}` 删除
- `/admin/users/{id}` 管理员改用户

也就是说，测试不再是“空白”，而是下一步该从主链路覆盖推进到修改型接口覆盖。

### 3.2 SSO 安全收口还没做完

当前实现已经是授权码换 token，但还没有 PKCE。

这并不代表现在不能用，但从安全和规范性角度看，后续仍值得补：

- `code_challenge`
- `code_verifier`
- 更清楚的登录失败分类

### 3.3 会话能力还比较轻

当前本站会话主要是本地 JWT，尚未形成更完整的会话管理能力，例如：

- refresh token
- 明确的登出/吊销
- 会话失效追踪

对开发期 MVP 足够，但从后端闭环看还不完整。

### 3.4 数据库维护仍偏开发态

当前仍依赖：

- `init_database.py` 里的 `drop_all/create_all`
- `scripts/migrate_add_sso_columns.py`

对于“空库为主”的开发阶段可接受，但如果环境开始稳定增多，仍建议逐步补成正式迁移体系。

### 3.5 后台运维能力还有扩展空间

审核链路已经能跑，但还缺少更偏运营和运维的能力，例如：

- 审核历史视图
- 更细的待审核筛选与分页元数据
- 分活动统计
- 更细的日志与审计记录

这些不是阻断项，但会影响平台后续运营效率。

## 4. 推荐的下一步后端优先级

如果继续整理后端，我建议顺序是：

1. 补 SSO 与审核主链路测试
2. 为关键链路增加更清楚的日志与错误分类
3. 继续把 `story.py` / `admin.py` / `interaction.py` 中较重的业务段落下沉到 service 层

这个顺序比马上做大规模结构重构更稳。
