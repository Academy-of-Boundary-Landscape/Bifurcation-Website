# 前端视觉风格指导

## 目标

本项目的前端视觉不应走“插画感”“梦幻感”或“泛科技紫色大屏”路线，而应收口为一套明确的风格：

- 黑白
- 锐利
- 极简
- 科幻

这套风格服务的不是单纯的“好看”，而是让树状叙事的复杂结构在视觉上仍然保持清晰、冷静、可信和具有未来感。

## 风格一句话定义

把这个网站理解为一台“叙事观测终端”，而不是普通内容社区。

它应该让用户感受到：

- 我在查看一棵不断分岔的世界线结构
- 我在进入一个冷静、克制、精密的叙事系统
- 节点、路径、审核状态、世界线切换都像终端信号，而不是社交平台卡片

## 核心视觉原则

### 1. 黑白优先

主色必须以黑、白、灰为绝对主导。

建议比例：

- `#000000` 到 `#111111` 作为主背景
- `#f5f5f5` 到 `#ffffff` 作为主文本
- `#5f5f5f` 到 `#9a9a9a` 作为辅助文本和弱边框

状态色只能作为少量强调：

- 成功：冷绿
- 警告：冷黄
- 错误：冷红
- 选中：偏冷白或低饱和蓝白

不要把彩色做成页面主体，也不要用大片高饱和光污染。

### 2. 锐利而非圆润

界面应偏向几何切割感，而不是圆润社交产品风格。

建议：

- 控件圆角偏小，甚至部分模块直接直角
- 分割线、边框、节点轮廓都要清楚可见
- 卡片之间依靠边界和节奏区分，不靠大面积花哨阴影

应避免：

- 过度圆角胶囊感
- 过厚的阴影和浮夸玻璃态
- 软萌、漂浮、果冻质感的组件语言

### 3. 极简但不单薄

极简不等于空。

页面应减少无意义装饰，但保留足够的结构信号：

- 细边框
- 网格节奏
- 清晰的分区
- 合理的留白
- 稀疏但精准的光效

用户第一眼应该感受到的是“秩序”，不是“热闹”。

### 4. 科幻感来自系统感

本项目的科幻感不该依赖廉价特效，而应来自：

- 信息像被精确编排过
- 页面像一个观察、筛选、跳转世界线的终端
- 动效像状态变化，不像娱乐动画

所以：

- 多使用扫描、切换、锁定、激活、聚焦这类语义
- 少使用弹跳、漂浮、卡通感反馈

## 页面气质定位

### 首页

首页应像“进入叙事系统的大门”。

关键词：

- 冷启动
- 观测台
- 世界线入口

建议表现：

- 大面积黑底
- 少量几何线条或网格
- 清晰的大标题
- 一到两个主 CTA

不要堆太多说明文案，也不要做成普通内容站首页。

### 故事册列表页

故事册列表页应像“任务列表 / 档案库 / 观测对象清单”。

关键词：

- 档案感
- 清单感
- 可扫描

建议表现：

- 卡片边界统一
- 文字信息有明显层级
- 活动状态用细标签标记
- 鼠标悬停时以边框和轻微发光反馈为主

### 故事树导航台

这是最核心的风格承载页。

关键词：

- 世界线观测台
- 路径锁定
- 节点激活

建议表现：

- 画布背景要克制，不能花
- 节点卡片以黑底、白字、细边框为主
- 当前选中节点要像被“锁定”
- 父链 / 当前路径高亮应清晰但不过度发光
- 右侧检视器应像“节点分析面板”

### 正文页

正文页需要比树图页更沉静。

关键词：

- 阅读
- 呼吸感
- 聚焦

建议表现：

- 字号、行高、段落间距要更舒服
- 背景仍然是暗色，但正文区对比度要足够
- 操作按钮不要压过正文
- 节点状态提示用顶部提示条或信息盒，不要做成噪声型提醒

### 创作页

创作页应像“接入世界线”的控制面板。

关键词：

- 输入
- 接续
- 提交

建议表现：

- 表单和前文摘要分区明确
- 输入区简洁、稳定、低干扰
- 提交区域要强但不刺眼
- 待审提示要有“流程状态”感

### 管理后台

后台应延续同一世界观，但更偏操作台。

关键词：

- 审核
- 控制
- 规则执行

建议表现：

- 信息密度略高于前台
- 审核状态明显
- 操作优先级分明
- 不要做成另一套完全不同的 UI 体系

## 组件级规范

### 按钮

主按钮：

- 白字深底或亮边深底
- 轮廓明确
- hover 以边框增亮、轻微内发光为主

次按钮：

- 边框按钮优先
- 不要用太多彩色填充按钮

危险按钮：

- 使用冷红
- 只在真正高风险操作中出现

### 卡片

卡片是本项目最常见的容器，必须统一。

建议：

- 深色底
- 细边框
- 小圆角或接近直角
- hover 只做轻微边框提升和阴影变化

不要：

- 使用厚重渐变卡片
- 使用夸张玻璃拟态

### 标签

标签用于状态识别，而不是装饰。

建议：

- 字号小
- 对比清楚
- 数量克制

状态标签视觉语义要稳定：

- `published`
- `pending`
- `archived`
- `ending`

不能今天一个配色，明天一个配色。

### 输入框

输入框应像终端输入区：

- 边框明显
- 背景克制
- 聚焦时边框变亮
- 不要做又厚又软的内阴影

### 节点卡片

节点卡片是项目最有辨识度的组件。

建议结构：

- 标题 / 分支名
- 一句摘要
- 作者
- 状态点

选中态应像“目标锁定”：

- 边框强化
- 外发光轻量增强
- 层级略高于其他节点

不要把节点卡片做成内容平台 feed 卡片。

## 版式与间距

### 总体节奏

页面要体现网格感和秩序感。

建议：

- 以 `8px` 为基础节奏
- 大区块用 `24 / 32 / 40`
- 小区块用 `8 / 12 / 16`

### 留白

留白应该服务于层次，而不是制造空洞。

黑白极简风格里，留白和留黑同样重要。

如果页面已经有复杂树图，就不要再在周围堆叠太多装饰元素。

## 字体与排版

建议整体采用更有机械感、终端感、几何感的字体策略。

至少在视觉指导层面应区分：

- 标题：更具识别度、更紧凑
- 正文：稳定、清晰、可长时间阅读
- 标签 / 数据 / 辅助信息：更窄、更规整

标题应短促、有力度，不宜太温柔。

## 动效原则

动效必须克制。

允许的动效方向：

- 页面载入时的渐入
- 节点激活时的轻微放大与描边增强
- 侧栏切换时的短距离滑入
- 视图聚焦时的平滑位移

不建议：

- 弹跳
- 过长的淡入淡出
- 高饱和霓虹闪烁
- 到处都在动

动效的关键词是：

- 扫描
- 锁定
- 聚焦
- 切换

## 图形元素建议

可少量使用这些图形母题：

- 网格
- 细线
- 角标
- 切角
- 目标框
- 光标式高亮
- 路径线

这些元素应该像“界面语言”的一部分，而不是插画。

## 不应采用的方向

以下方向应主动避免：

- 紫色泛滥的通用 AI 科技风
- 赛博朋克霓虹夜店风
- 社交媒体卡片堆叠风
- 二次元梦幻发光风
- 花里胡哨的大屏可视化风
- 过于圆润的消费级 SaaS 风

## 设计落地建议

在真正修改页面之前，建议先统一这些基础层：

1. 先定义全局设计 token
   - 背景色
   - 文本色
   - 边框色
   - 状态色
   - 阴影
   - 圆角
   - 动效时长

2. 再统一核心容器
   - 顶部导航
   - 内容卡片
   - 检视器面板
   - 表单输入区

3. 最后统一故事树专属组件
   - 节点卡片
   - 路径高亮
   - 检视器
   - 阅读入口
   - 创作入口

## 最终判断标准

如果风格落地正确，用户看到页面时应该觉得：

- 结构清楚
- 气质冷静
- 信息可信
- 世界线系统感很强
- 创作和阅读都被同一套视觉语言包住

而不是觉得：

- 花
- 乱
- 像模板站
- 像普通社区
- 像另一个泛用后台系统
