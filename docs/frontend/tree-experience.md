# 前端树状小说体验统一草案

## 核心判断

这个项目最重要的页面，不应该只是“书籍详情页”或“树图页”，而应该是一个统一的“故事树导航台”。

这个页面要同时完成三件事：

- 帮读者看懂整棵故事树
- 帮读者快速进入正文阅读
- 帮创作者在恰当的位置产生续写或分支创作的冲动

因此，统一方案不应再把“阅读视图”和“图谱视图”理解为两套割裂产品，而应该让它们围绕同一个核心页面协同工作。

## 统一页面目标

目标页面应该具备下面的能力：

- 在一个可拖拽、可缩放的主画布中展示整棵树
- 点击任意节点后，在固定侧栏中查看该节点信息和预览
- 从侧栏一键进入正文、完整分支阅读或创作入口
- 让用户始终知道自己当前在整棵树中的位置

这个页面的本质不是“流程图”，而是“叙事导航台”。

## 推荐统一结构

建议采用双区结构，而不是满屏树图。

### A. 主画布

主画布负责展示整棵树的结构信息：

- 支持拖动
- 支持缩放
- 支持一键重置视图
- 支持聚焦当前节点
- 支持高亮当前阅读路径

节点在画布中只展示轻量信息：

- 标题或分支名
- 作者
- 状态
- 一句摘要
- 轻量热度信息

不要在节点卡片里塞长正文、评论区或复杂按钮。画布负责导航，不负责深度阅读。

### B. 右侧检视器

右侧固定信息面板是这个页面的第二核心。

默认未选中状态下，显示作品级信息：

- 作品简介
- 节点总数
- 当前活跃分支数
- 推荐阅读入口
- 最近更新节点

选中节点后，切换为节点检视模式：

- 标题 / 分支名
- 作者
- 创建时间
- 状态
- 节点摘要
- 所属路径位置
- 父节点信息
- 子分支数量

同时给出明确动作：

- `查看正文`
- `查看完整分支`
- `沿此续写`
- `创建分支`
- `跳转父节点`
- `查看子分支`

## 用户体验目标

### 1. 对新读者

新读者进入页面后，首先应该获得“方向感”，而不是信息压力。

需要马上看懂：

- 这本书大概有多少条世界线
- 哪些区域最值得读
- 应该从哪里开始进入

所以页面首次加载时，应该默认：

- 视图停留在整树概览
- 高亮主干或推荐阅读路径
- 右侧显示作品导览，而不是空白

### 2. 对正在阅读的用户

正在阅读的用户最怕迷路。

这个页面必须让他们快速知道：

- 我现在这一节点在哪里
- 它的前文是什么
- 它还有哪些平行分支
- 我能不能切换到别的世界线继续看

因此，当前路径高亮是必须项，不是加分项。

### 3. 对创作者

创作者的动力不是来自“有个投稿按钮”，而是来自“这个节点让我想接着写”。

因此页面要把创作入口放在节点上下文里，而不是孤立地放在别处。

理想体验是：

- 用户点开节点
- 在侧栏读完摘要和上下文
- 很自然地看到：
  - 这个节点还没有后续
  - 这个节点正在成为分歧点
  - 这个分支很活跃
  - 这里适合继续展开

然后点击：

- `沿此续写`
- `创建分支`

## 核心阅读体验设计

为了让树状小说有好的阅读体验，这个页面必须明确把“结构探索”和“正文阅读”分开。

结构探索发生在导航台里。

正文阅读发生在：

- `StoryNodePage`
- `StoryLineagePage`

导航台的工作是帮助用户决定“接下来读哪一段”，而不是直接在图里读完整小说。

因此：

- 画布节点只给轻量预览
- 右侧检视器提供更完整摘要
- 真正正文通过“查看正文”进入详情页
- 真正沉浸式阅读通过“查看完整分支”进入连续阅读页

这样可以避免图谱把阅读体验弄碎。

## 核心创造性体验设计

为了发挥用户创造性，页面需要让“可能性”可见。

建议重点强化下面这些信号：

- 哪些节点是分歧点
- 哪些节点还没有后续
- 哪些分支正在快速增长
- 哪些节点已经完结
- 哪些区域适合继续开新世界线

建议为创作者提供筛选模式：

- 只看未完结节点
- 只看叶子节点
- 只看最近活跃节点
- 只看高热分歧点

这样创作者打开这个页面时，不是盯着一整棵树发呆，而是能快速找到“我可以接在哪里写”。

## 建议的页面状态

### 初始状态

- 主画布展示整树
- 默认缩放到可理解范围
- 高亮推荐主干
- 右侧显示作品导览

### 选中节点状态

- 主画布高亮当前节点及其父链
- 右侧显示节点摘要与操作入口
- 保持画布位置不被强行打断

### 从阅读页返回状态

- 自动聚焦用户刚才所在节点
- 自动高亮该节点所属路径
- 右侧直接显示该节点详情

这个返回体验很关键，它决定用户是否会把导航台当成“有用工具”。

## 需要避免的误区

- 不要把这个页面做成流程图编辑器风格
- 不要在画布节点中塞入长篇正文
- 不要让所有节点默认完全展开
- 不要让用户点了节点之后还要再找半天入口
- 不要让图谱喧宾夺主，压过阅读本身

## 与当前代码的对应关系

当前项目已有的基础是够用的：

- `frontend/src/pages/books/BookDetailPage.vue`
  - 可以演化为统一导航台入口
- `frontend/src/components/story/StoryTreeFlow.vue`
  - 可以继续承担主画布
- `frontend/src/components/story/StoryTreePanel.vue`
  - 可以作为后续辅助目录区或折叠面板
- `frontend/src/pages/story/StoryNodePage.vue`
  - 继续承担单节点正文页
- `frontend/src/pages/story/StoryLineagePage.vue`

因此不需要推倒重来，但需要把这些页面的关系重新收口。

## 技术实现建议

### 1. 保留现有 Vue 技术栈

主框架不需要更换：

- Vue 3
- TypeScript
- Vue Query
- Pinia
- Naive UI

### 2. 故事树实现拆层

建议把故事树相关实现拆成三层：

- 数据适配层
  - `StoryNodeTreeItem[] -> graph nodes / edges / path highlight`
- 交互状态层
  - 当前选中节点
  - 当前高亮路径
  - 当前视图位置
- 渲染层
  - 画布
  - 右侧检视器
  - 目录树

### 3. 图谱布局方向

当前图谱的手写坐标适合临时演示，不适合正式产品。

后续推荐方向仍然是：

- 渲染交互：`@vue-flow/core`
- 树布局：`d3-hierarchy/tree`

但这一步应放在信息结构明确之后，而不是先动底层库。

## 建议组件结构

建议后续收口为下面这组组件：

- `StoryTreeWorkspace`
  - 整个导航台容器
- `StoryTreeCanvas`
  - 主画布
- `StoryTreeInspector`
  - 右侧检视器
- `StoryTreeToolbar`
  - 缩放、重置、筛选、路径聚焦
- `StoryTreeSidebar`
  - 可选的目录树或筛选区

这里最重要的是 `Canvas + Inspector` 这对主从关系。

## 实施顺序

### 第一期：统一页面骨架

- 把 `BookDetailPage` 改造成统一导航台
- 确定 `Canvas + Inspector` 双区布局
- 打通点击节点后显示侧栏详情
- 打通“查看正文 / 查看完整分支 / 沿此续写 / 创建分支”

目标是先把核心体验跑通。

### 第二期：路径感和阅读联动

- 从 `StoryNodePage` 返回时自动聚焦当前节点
- 从 `StoryLineagePage` 返回时高亮整条分支
- 加入父链高亮和兄弟分支切换

目标是减少迷路。

### 第三期：创作辅助

- 增加叶子节点筛选
- 增加未完结节点筛选
- 增加活跃分支筛选
- 在侧栏强化“适合续写”的提示

目标是增强创作欲。

### 第四期：图谱升级

- 引入新的布局算法
- 优化大树性能
- 优化移动端和触控体验

目标是把临时图谱升级成正式产品能力。

## 结论

统一版本的前端方向应该是：

- 以“整棵树画布 + 右侧节点检视器”为核心页面结构
- 让树图承担导航与理解结构的任务
- 让正文阅读继续回到节点页和连续阅读页
- 让创作入口围绕具体节点出现，而不是孤立存在

对树状故事网站来说，最佳体验不是“图越大越好”，而是：

- 用户能看懂整棵树
- 用户能顺畅进入阅读
- 用户能在节点上下文中自然产生创作冲动
