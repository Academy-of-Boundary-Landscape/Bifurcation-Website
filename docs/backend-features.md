# 后端功能与业务规则

本文档关注“系统在做什么”和“规则是什么”，而不是逐字段列接口。

## 1. 系统定位

这是一个树状叙事平台后端。核心不是线性文章发布，而是：

- 围绕活动组织内容
- 节点之间形成树状分支
- 普通用户投稿默认进入审核
- 审核通过后进入公开阅读和互动

## 2. 权限模型

当前角色：

- `admin`
  - 后台管理、创建根节点、审核、用户管理
- `writer`
  - 普通创作者
- `banned`
  - 封禁角色，不应继续参与正常业务

权限判断目前仍然完全落在本站本地数据库：

- Casdoor claims 只会在“首次创建本地用户”时参与角色初始化
- 是否有后台权限，仍由本地 `users.role` 控制

## 3. 当前认证模型

当前后端已经进入 SSO 迁移期，但业务会话仍是本站本地 token。

实际链路：

1. 用户去 Casdoor 登录
2. 后端通过 `/auth/sso/exchange` 确认身份
3. 后端映射或创建本地用户
   - 如果 Casdoor claims 命中管理员映射规则，新建用户可初始化为 `admin`
4. 后端签发本站 JWT
5. 后续所有业务接口继续使用本站 JWT

这保证了两件事：

- 登录逻辑可以交给 Casdoor
- 业务权限、作者归属、管理员控制仍由本站掌握

## 4. 用户模型

本地 `User` 现在同时承担两类职责：

- 业务身份
  - 作者、评论者、点赞者、通知接收者
- 权限与画像
  - `role`
  - `is_active`
  - `bio`
  - `avatar`
  - `display_name`

SSO 接入后新增的映射字段：

- `auth_provider`
- `auth_subject`
- `auth_user_id`
- `auth_last_sync_at`

这些字段的作用不是替代本地用户，而是把外部身份和本地业务主体绑定起来。

当前应以 `auth_provider + auth_subject` 作为 SSO 唯一身份键，而不是邮箱。

这意味着：

- 本地邮箱现在只是用户资料字段，不再承担唯一身份标识职责
- 自动按邮箱绑定旧账号时，如果同一邮箱对应多个本地账号，后端会拒绝自动绑定

## 5. 故事活动与树结构

## 5.1 活动 `StoryBook`

平台按活动组织故事，不是全站任意散点投稿。

关键控制字段：

- `phase`
- `allow_new_nodes`
- `start_at`
- `writing_end_at`
- `showcase_end_at`

阶段含义：

- `drafting`
  - 筹备期
- `writing`
  - 创作期
- `showcase`
  - 展示期
- `archived`
  - 历史归档期

## 5.2 节点 `StoryNode`

每个节点是故事树里的一个创作单元。

关键关系：

- `parent_id`
  - 当前节点续写自哪个节点
- `root_id`
  - 当前节点属于哪棵树
- `book_id`
  - 当前节点属于哪个活动

关键状态：

- `pending`
- `published`
- `archived`

关键可见性：

- `private`
- `public`
- `unlisted`

## 6. 节点提交与审核规则

普通用户提交节点时，系统重点控制以下条件：

- 活动必须允许创作
- 普通用户通常不能创建根节点
- 父节点必须满足可续写条件
- 如果父节点已标记为结尾，普通用户不能继续分支

状态流转大致如下：

- 普通用户投稿：`pending`
- 管理员直接创建：`published`
- 审核通过：`pending -> published`
- 审核驳回：`pending -> archived`
- 作者/管理员删除：`* -> archived`

## 7. 阅读与发现

后端目前明确区分两类读取策略：

- 轻量列表/树读取
  - 用于列表页、树视图、发现流
  - 不返回大正文
- 深读读取
  - 用于节点详情、路径阅读、审核
  - 返回完整正文和审核信息

这样做是为了防止树接口一次性拉回大量正文内容。

发现能力包括：

- 最新动态
- 热门榜
- 搜索已发布节点

## 8. 互动能力

目前支持：

- 点赞
- 评论
- 评论软删除
- 通知列表与已读管理

通知覆盖的主要事件：

- 节点被续写
- 节点被点赞
- 节点被评论
- 审核通过
- 审核驳回

## 9. 管理后台能力

管理员当前拥有的核心能力：

- 查看待审核节点
- 审核节点状态
- 查看用户列表
- 修改用户角色或激活状态
- 查看仪表盘统计
- 管理活动

注意：

- Casdoor 只是登录入口，不会在每次登录时自动重写本地管理员权限
- 管理员账号绑定 SSO 时，建议避免自动邮箱合并造成误绑定

## 10. 当前收口状态

已经明确的方向：

- 本地密码接口已经从主 API 中移除
- 管理员初始化直接创建绑定 SSO subject 的本地管理员账号
- 后续应继续围绕 SSO 方案收口，而不是再恢复旧密码逻辑

如果要继续推进后端整理，优先级建议是：

1. 把数据库迁移从脚本升级为正式迁移
2. 增加 SSO 登录联调与用户绑定测试
3. 继续把路由中的业务逻辑抽到服务层
